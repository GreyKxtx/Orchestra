# Orchestra Desktop

Tauri-оболочка поверх `orchestra web`: приложение запускает ядро как дочерний
процесс, открывает окно на его адрес и штатно гасит ядро при закрытии окна.
Внутри окна — тот же `ui/web`, что и в браузере; в оболочке нет ни IPC, ни
своего фронтенда. Спека: `docs/superpowers/specs/2026-09-09-desktop-shell-design.md`.

## Как это работает

1. Проект: только аргумент командной строки. Без аргумента оболочка ничего не
   угадывает — окно открывается на стартовом экране страницы, где уже есть и
   список запомненных проектов, и «Открыть папку…», и «Клонировать с GitHub».
   Ни `desktop.json`, ни `projects.json` оболочка при старте не читает: этот
   список отдаёт странице само ядро. Открытый проект записывается в
   `~/.orchestra/desktop.json` как `last_project`.
2. Ядро: `orchestra[.exe]` рядом с exe оболочки, иначе `orchestra` из `PATH`
   (dev-режим, о чём пишется в stderr). Запуск:
   `orchestra web --workspace-root <dir> --no-open --port 0 --init --announce`.
3. Ядро печатает одну JSON-строку (объект discovery) в stdout — оболочка берёт
   из неё `url` и `token` и открывает окно на `<url>/?token=…`; сервер ставит
   cookie и редиректит на `/`.
4. Закрытие окна: оболочка закрывает stdin ядра (сигнал завершения под
   `--announce`), ждёт до 3 с, затем kill.

## Сборка и запуск

Нужны Rust stable (rustup), на Windows — MSVC Build Tools и WebView2; на Linux —
пакеты из `.github/workflows/ci.yml` (job `desktop`).

```bash
# ядро рядом с оболочкой (иначе берётся из PATH)
node ui/desktop/scripts/build-sidecar.mjs
cd ui/desktop/src-tauri
cargo run -- /path/to/project      # или без аргумента
cargo test                         # boot.rs и sidecar.rs
```

## Части

- **A — реестр проектов** (сделано): несколько ядер в одном `orchestra web`,
  `/api/projects`, `/ws?project=`, cookie-аутентификация.
- **B — оболочка** (этот каталог): окно, sidecar, выбор проекта.
- **C — упаковка**: `bundle.externalBin`, инсталляторы, подпись, автообновление.
  До C `cargo build` собирает только оболочку; ядро кладётся рядом скриптом.

Переключатель проектов, список сессий по проектам и настройки живут в `ui/web`
и делаются там.

## Полоса проектов

Окно перечисляет все запомненные проекты вдоль левого края. Плашка показывает,
что проект делает: работает, ждёт вашего ответа, открыт и простаивает или
просто запомнен и закрыт. Клик по закрытому проекту открывает его; правый клик
предлагает «Закрыть проект» (он останется в списке) и «Убрать из списка».

Сам список — `~/.orchestra/projects.json`. Закрытие проекта его не меняет; из
списка убирает только «Убрать из списка».

Страницу отдаёт `orchestra web` на loopback, поэтому с точки зрения Tauri это
удалённый URL, и по умолчанию доступа к оболочке у него нет.
`src-tauri/capabilities/core-page.json` даёт ей ровно две возможности: показать
уведомление, когда фоновому проекту нужен ответ, и открыть выбор папки при
добавлении проекта. Больше ничего.

Разрешение выдано на `http://127.0.0.1:*`, потому что порт ядра выбирается в
момент запуска и записать его в файл заранее нельзя. Чтобы эти две возможности
не достались заодно любой другой странице на loopback, окно закреплено за тем
origin, который ядро объявило: `on_navigation` в `main.rs` отклоняет переход
куда-либо ещё.

`"csp": null` в `tauri.conf.json` — не дыра: собственного фронтенда у оболочки
нет (`frontendDist` — заглушка), и настройка эта касается только того, что
отдаёт сам Tauri. Политику для страницы ставит `orchestra web` заголовком
`Content-Security-Policy` — см. `internal/webtransport/server.go`.
