# Orchestra Web

Браузерный клиент ядра. Поднимается командой `orchestra web` и обслуживается
самим ядром: страница ходит в него по WebSocket (`/ws`, JSON-RPC без
LSP-обрамления, одно сообщение на кадр) и по нескольким HTTP-ручкам
(`/api/projects`, `/api/health`). Тот же самый интерфейс показывает и оболочка
десктопа — см. `ui/desktop/`.

## Откуда берётся страница

Рендерер чата — общий с расширением VS Code. Фрагменты лежат в
`ui/vscode/media/chat-src/` и **не копируются**: сборщик читает их на месте,
поэтому разойтись двум копиям просто негде. Собственные файлы веба — хост и
адаптеры вокруг этого рендерера:

| Что | Где |
|---|---|
| Разметка | `index.src.html` |
| Хост и адаптеры | `src/*.js` (`00-web-prelude` … `75-turn-rail`) |
| Настройки | `src/settings/` |
| Сборка | `scripts/bundle-web.mjs` → `static/` |
| Отдача в Go | `embed.go` (`//go:embed all:static`) |

`static/` — сборочный артефакт, но он **закоммичен**: так `go build` не
зависит от установленного node. Точно так же устроен `ui/vscode/media/`.

Роль хоста в вебе играет адаптер: рендерер шлёт ему те же сообщения, что и
хосту расширения (`applyPending`, `discardPending`, `send`, …), а адаптер
переводит их в RPC ядра. Поэтому фича, доделанная в одном клиенте, не требует
второй реализации в другом — но требует, чтобы оба хоста отвечали рендереру
одинаковыми сообщениями.

## Работа с кодом

```bash
node scripts/bundle-web.mjs      # пересобрать static/
node scripts/watch-web.mjs       # то же в режиме наблюдения
node scripts/adapter-test.mjs    # тесты адаптера (настоящий бандл в VM-песочнице)
node scripts/check-web.mjs       # бандл свеж, id из разметки существуют, имена не дублируются
```

Правьте `src/` и фрагменты в `ui/vscode/media/chat-src/`, а не `static/`:
собранный бандл перезаписывается и любая правка в нём пропадёт. `check-web.mjs`
пересобирает и сравнивает — забытая пересборка падает здесь, а не у
пользователя. Оба скрипта запускаются в CI.

`adapter-test.mjs` гоняет настоящий `static/web.bundle.js` в песочнице `vm` с
заглушками DOM, WebSocket и fetch, поэтому тест видит ровно тот код, который
получит браузер.
