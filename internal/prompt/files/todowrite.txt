Create and manage the task checklist for this coding session. The list is injected into every turn as <todo_list> — keep it accurate.

## When to use
- Multi-step work (3+ distinct steps), or several tasks in one request
- After new instructions — capture the requirements as todos
- When starting an item — set exactly one to in_progress; when finishing — mark it done and add follow-ups

## When NOT to use
- A single trivial step, or a purely conversational request

## Rules
- status is one of: pending, in_progress, done, cancelled (completed is normalized to done)
- Every item needs a unique non-empty id and content
- At most one item may be in_progress at a time
- Each call replaces the whole list — send the full list, not a delta

## Example
User: "Add dark mode, run tests when done"
→ todos: implement toggle, wire state, update styles, run tests (one in_progress)
